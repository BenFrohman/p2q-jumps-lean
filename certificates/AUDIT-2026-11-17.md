# Certificate audit, 17 Nov 2026 (America/Chicago)

Rules audited (Benjamin Stanley Frohman, 17 Nov 2026, 1:33–1:56 AM CT):

1. Every lake build and certificate attempt (pass, fail or partial) runs from this repo's own committed
   `lake-manifest.json` and ships with that manifest, its sha256, the commit, `lean-toolchain`, the
   Mathlib rev, elan/lake versions, the full build log and the `#print axioms` output.
   Hand-written summaries never count as certificates.
2. No dummy certificates: the final pass rests only on the real Lean kernel. External tools (PARI,
   Python/SymPy, `scripts/p7/gen_kernel.py`) may only generate data that the kernel then checks; they
   never prove or pass anything on their own.

## Mechanism from now on

`scripts/cert-bundle.sh` runs `lake build` and `lake env lean AxiomAudit.lean` from the committed
`lake-manifest.json` (it refuses to build if the manifest differs from the committed one) and saves
`lake-manifest.json`, `lake-manifest.json.sha256`, `lean-toolchain`, `lakefile.toml`, `env.txt` (commit,
Mathlib rev, elan/lake/lean versions, exit codes), `lake-build.log`, `print-axioms.log` and
`SHA256SUMS`, all captured verbatim.

- **Only `certificates/passed/<time>-CT-<commit>/` is a certificate.** A run lands there only if
  `lake build` exits 0, `#print axioms` exits 0, and every axiom line lists only propext,
  Classical.choice and Quot.sound. Each such directory carries a `CERTIFICATE` file.
- **Anything else goes to `certificates/attempt-logs/<time>-CT-<commit>/`** with
  `FAILED-NOT-A-CERTIFICATE.txt`. A failed or partial build is a log only and certifies nothing.

CI (`certify.yml`) runs the same script. On success it uploads `certificate-<sha>` from
`certificates/passed/`; on failure it uploads `failed-attempt-log-NOT-A-CERTIFICATE-<sha>` from
`certificates/attempt-logs/`.
